# 子流程：kb-query

回答半导体前后段的工艺与排查问题。**只读，不改动任何文件。**

## 输入

用户的自然语言问题，例如：
- 「后段厂 Wire Bond 站点 WIP 堆积，可能原因有哪些，怎么排查」
- 「光刻 CD 超规格怎么查」
- 「塑封孔洞的根因有哪些」

## 步骤

**1. 定位切入点**

读 `build/index.json`，用问题中的关键词匹配 `keywords` 字段，找到相关实体与 kb 实例。
若 `build/index.json` 不存在或早于本体文件的修改时间，先跑 `python scripts/build_index.py`。

优先级：先找 kb 实例（已有成型的排查知识），没有再找本体异常实体。

**2. 沿图展开**

读 `build/graph.json`：

- 从异常节点沿 `in_adjacency` 的 `may_cause` 反查根因
- 沿 `out_adjacency` 的 `detected_at` 找检出点、`mitigated_by` 找处置动作
- 沿 `blocks` 判断影响范围
- 沿 `refines` 向上找 core 层通用概念，向下找细化异常
- 若问题涉及位置（"某站点"），用 `routes` 里的 `anomalies_detected_here` 确认该站点会检出哪些异常，以及上游有哪些站点

**3. 组织答案**

优先用 kb 实例的 `possible_causes` 结构。每条根因必须带 `discriminator`——
**这是知识库最有价值的字段**：只列"可能原因"是常识罗列，任何人都能说出来；
说清"怎么把这条与其他条区分开"才是可执行的排查。

**4. 标注溯源**

每个结论后面括号标出来源本体 ID 或 kb 实例 ID。这不是为了好看：
用户需要能自己去核对，也需要在结论错了的时候知道该改哪个文件。

## 输出格式

见 `output-contracts/query-answer.md`。

## 边界

**第一步先跑 `python scripts/ask.py "<用户原问>"`。** 不要靠肉眼读
`competency-questions.yaml` 判断能不能答 —— 那是凭印象,脚本才是可复核的。

    python scripts/ask.py "颗粒突增可能是什么原因"      # 判定 + 答案路径
    python scripts/ask.py "..." --probe                # 顺便沿边走一遍看空不空
    python scripts/ask.py "..." --json                 # 结构化,便于串流程

退出码即判定:`0` 可答 | `2` 明确超出范围 | `3` 清单里没有这个问题。

- **`0`**:按输出的 `答案路径` 沿图遍历取答案。命中条目带 `caveat` 的
  要一并说明限制(例如 CQ16 只对量测/测试机台成立)。
- **`2`**:照输出的 `缺什么` / `要答得了得先建` 回复。若脚本给了
  **相近的可答问题**,把改写建议一起给用户 —— 多数越界只是措辞问题。
- **`3`**:清单没覆盖。先判断这个问题**该不该**能答:能沿图走通就补一条
  `in_scope`,走不通就补一条 `out_of_scope`。不要跳过这步直接凭模型知识作答。
  也可能只是 `match_terms` 没覆盖这种问法 —— 输出里的"分数不足的候选"
  若明显对得上,补词而不是新增条目。

判定之后再按清单条目取答案:

- 问题落在 `in_scope`:按 `answered_via` 指的路径沿图遍历取答案。
  条目带 `caveat` 的要一并说明限制(例如经营传导只有定性没有量化)。
- 问题落在 `out_of_scope`:**直接说超出当前本体范围**,引用该条的
  `missing`(缺的是什么)与 `precondition`(要答得了得先建什么)。
  这类问题**不要用模型知识硬编答案** —— 库外知识伪装成库内知识,
  溯源链断掉而且没人知道断了,比答不出来坏得多。
- 两边都不落:按下面这条处理,并提示这个问题本身值得进清单。

- 本体里没有的东西**不要编**。可以说"本体中未覆盖，以下是基于通用制造知识的推断"，
  并明确标注这部分未沉淀，建议走 `ontology-build` 补入。
- 不要把 `provenance.confidence` 为 `low` 的结论说得像定论，标出可信度。
- 不涉及具体工厂实时数据。本项目无内部接口，回答的是**知识层面**的
  "可能原因与排查路径"，不是"你们厂现在是哪个原因"。
